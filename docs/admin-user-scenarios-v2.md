# OrderFit 관리자 사용 시나리오 2차

## 기준 기능

이 문서는 현재 배포된 OrderFit 프로토타입의 기능을 기준으로 한다.

- 영수증 사진 등록: 발주 날짜·업체 선택 후 이미지 업로드
- 날짜별 영수증 목록: 일자별 거래 건수·합계·업체·대표 품목 표시
- 영수증 검토/확정: 업체·날짜·품목·품목별 금액 수정 및 확정
- 영수증 필터: 날짜·업체·상태·운영 영역(홀/주방)
- 홀/주방 분리 품목 관리
- 품목 상세: 재고·단가·날짜별 발주 이력
- 업체 상세: 누적 발주액·거래 건수·날짜별 주문·주문 품목

## 1. 운영 상태 정의

| 상태 | 의미 | 관리자 행동 | 재고/비용 반영 |
| --- | --- | --- | --- |
| 검토 필요 | 사진은 등록됐지만 OCR 결과를 확인하지 않은 상태 | 원본과 행 단위 데이터를 검토·수정 | 반영 전 |
| 확정 | 관리자 검토가 완료된 발주 | 이력 조회, 단가·업체 분석에 사용 | 반영 |
| 원본 없음 | 과거 수기 기록 등 사진이 없는 발주 | 필요 시 증빙 추가, 거래 내역만 확인 | 기존 확정 데이터 기준 |

## 2. 시나리오 A — 배송 직후 영수증 등록부터 확정까지

### 시작 조건

- 식자재 업체가 오전 배송을 완료했다.
- 관리자는 종이 영수증을 받았고, 주방 입고 수량도 확인했다.

### 흐름

1. 관리자는 홈 오른쪽 상단의 `+` 버튼을 누른다.
2. `영수증 등록` 다이얼로그에서 발주 날짜를 배송일로 지정한다.
3. 업체를 선택한다. 목록에 없으면 `기타 업체`를 선택해 후속 등록 대상으로 남긴다.
4. 카메라로 영수증을 촬영하거나 이미지를 선택한다.
5. `OCR 분석 시작`을 누른다.
6. 시스템은 해당 날짜의 영수증 목록에 `검토 필요` 상태의 거래를 생성한다.
7. 관리자는 날짜별 목록에서 새 거래를 선택한다.
8. 원본 사진을 확인하면서 업체명, 발주 날짜, 품목명, 각 품목 금액을 수정한다.
9. 누락 품목이 있으면 `품목 행 추가`를 누른다.
10. `검토 완료 및 발주 확정`을 누른다.

### 관리자 판단 기준

- 영수증 총액과 입력한 품목 금액의 합계가 일치해야 한다.
- 동일 날짜·동일 업체 영수증이 여러 건이면 배송 분할인지 중복 등록인지 확인한다.
- 주방 식자재인지 홀 소모품인지에 따라 이후 재고 확인 탭을 결정한다.

### 기대 결과

- 영수증 상태가 `확정`으로 변경된다.
- 날짜별 합계 및 업체별 거래에서 해당 발주를 조회할 수 있다.
- 확정 내역은 품목별 단가·발주 이력 분석의 근거가 된다.

## 3. 시나리오 B — 당일 미확정 영수증만 모아서 처리

### 상황

점심 영업 중 영수증 3건이 등록됐지만 검토를 미뤄 두었다. 마감 전 모든 건을 확정해야 한다.

### 흐름

1. 하단 메뉴의 `영수증`을 누른다.
2. 상태 필터를 `검토 필요`로 설정한다.
3. 필요하면 날짜 필터를 오늘로, 운영 영역 필터를 `주방` 또는 `홀`로 설정한다.
4. 검색 결과 건수를 확인한다.
5. 각 거래를 차례로 열고 원본 사진과 OCR 항목을 검토한다.
6. 금액·품목이 맞으면 확정하고, 사진이 불명확하면 재촬영 요청 또는 직접 입력으로 처리한다.

### 완료 조건

- 상태 필터 결과가 0건이 된다.
- 마감 전에 미확정 영수증이 남지 않는다.

### 운영 규칙

- 관리자는 매일 마감 전 `검토 필요 0건`을 확인한다.
- 24시간 이상 미확정이면 점장에게 알림을 보낸다.
- 금액이 20만 원 이상인 영수증은 관리자 확정을 필수로 한다.

## 4. 시나리오 C — 특정 날짜 발주 품목을 주방에 답변

### 상황

주방장이 “8월 5일에 포장 용기와 냅킨을 얼마나 주문했는지” 질문한다.

### 흐름

1. 영수증 화면에서 날짜 필터를 `2026-08-05`로 설정한다.
2. 운영 영역을 `홀`로 설정한다.
3. 날짜 카드에서 `그린패키지` 거래를 선택한다.
4. 상세에서 총 발주금액과 품목 행을 본다.
5. 원본 영수증 사진과 함께 포장 용기·냅킨·쇼핑백의 금액을 답변한다.

### 관리자에게 보여야 할 정보

- 해당 날짜 전체 거래 건수와 합계
- 업체별 영수증 금액
- 품목명, 규격/수량, 품목 금액
- 영수증 원본 이미지
- 확정 여부와 확정 시각

## 5. 시나리오 D — 홀과 주방의 발주 책임 분리

### 상황

주방장은 양파와 한우 등심을, 홀 매니저는 포장 용기와 냅킨을 관리한다. 관리자는 두 영역의 품목을 분리해서 확인해야 한다.

### 주방 운영 흐름

1. `품목` 메뉴에서 `주방` 탭을 선택한다.
2. 품목 카드에서 현재고, 최소재고, 최근 단가를 확인한다.
3. `양파` 또는 `한우 등심`의 `상세 보기`를 누른다.
4. 날짜별 발주 이력에서 업체·수량·단가·금액을 확인한다.
5. 최근 단가가 평균보다 높으면 업체 상세로 이동해 대체 거래처를 검토한다.

### 홀 운영 흐름

1. `품목` 메뉴에서 `홀` 탭을 선택한다.
2. 포장 용기·냅킨·쇼핑백의 현재고와 최소 기준을 확인한다.
3. 재주문 필요 품목은 업체 상세에서 최근 주문 단가와 주문 수량을 확인한다.
4. 예약·배달 예상량을 고려해 다음 발주 요청을 준비한다.

### 책임 경계

| 항목 | 주방장 | 홀 매니저 | 관리자 |
| --- | --- | --- | --- |
| 사용량/재고 실사 | 입력 | 입력 | 조정 승인 |
| 영수증 촬영 | 가능 | 가능 | 가능 |
| 영수증 확정 | 요청 | 요청 | 최종 확정 |
| 품목/업체 마스터 수정 | 조회 | 조회 | 수정 |
| 비용 분석 | 조회 | 조회 | 분석·의사결정 |

## 6. 시나리오 E — 업체별 월간 발주를 검토하고 증빙 확인

### 상황

월말에 푸른식자재 발주액이 높아진 이유를 확인해야 한다.

### 흐름

1. `업체` 메뉴에서 `푸른식자재` 카드를 선택한다.
2. 이번 달 발주금액, 거래 건수, 최근 발주일, 주요 주문 품목을 확인한다.
3. `거래 상세 보기`를 누른다.
4. 날짜별 주문 내역에서 금액이 큰 날짜를 선택한다.
5. 해당 날짜의 영수증 원본과 품목별 금액을 확인한다.
6. 양파·대파·감자 중 증가 원인 품목을 확인하고, 필요한 경우 품목 상세로 이동해 단가 추이를 본다.

### 의사결정 예시

| 확인 결과 | 관리자 조치 |
| --- | --- |
| 구매 수량 증가 | 예약/행사/메뉴 변경 여부 확인 |
| 단가 상승 | 대체 업체 비교 또는 단가 협상 |
| 동일 영수증 중복 | 중복 건 취소 또는 조정 기록 |
| 원본 없음 | 거래처에 증빙 재요청 |

## 7. 시나리오 F — 단가 이상 알림을 비용 절감으로 연결

### 상황

대시보드에서 한우 등심 단가 상승을 확인했다.

1. 알림 또는 품목 목록에서 `한우 등심`을 선택한다.
2. 이번 달 발주금액, 평균 단가, 최근 단가를 비교한다.
3. 날짜별 발주 이력에서 상승이 시작된 날짜를 찾는다.
4. 해당 발주 업체와 영수증을 확인한다.
5. 업체 상세에서 거래 빈도와 주문 품목을 확인한다.
6. 다음 발주 전 대체 업체 견적, 주문 단위, 납기일을 비교한다.
7. 결정 결과를 업체 메모 또는 다음 발주 요청에 남긴다.

## 8. 모바일 운영 원칙

- 당일 업무는 홈 → 영수증 → 검토/확정 흐름으로 3분 이내 처리한다.
- 긴 표는 모바일에서 거래 카드로 읽고, 원본 사진은 상세 화면에서 즉시 연다.
- 하단 메뉴는 홈·영수증·업체·품목·재고로 고정한다.
- `검토 필요` 상태는 색상과 배지로 명확히 구분한다.
- 중요한 확정 작업은 큰 단일 CTA로 제공한다.

## 10. 3차 개발 연결 과제

1. 이미지 스토리지·DB·실제 OCR API 연동
2. OCR 신뢰도, 합계 불일치, 중복 영수증 검증
3. 재고 입고 자동 반영 및 사용량/폐기 거래 원장
4. 날짜별/업체별 내역에서 실제 영수증 원본의 영구 링크 제공
5. 사용자 권한, 승인 단계, 감사 로그
