# OrderFit 실제 사용자 기반 테스트 시나리오

## 목적

식당 운영 중 실제로 발생하는 `가입 → 매장 설정 → 영수증 등록 → 검토·확정 → 재고·비용 확인` 흐름을 역할별로 검증한다. 테스트 데이터는 반드시 `QA` 접두어로 만들고, 종료 후 관리자 승인 아래 삭제한다.

## 테스트 계정·데이터

| 구분 | 값 |
| --- | --- |
| 관리자 | `qa-admin@example.com` / 관리자 |
| 주방 담당 | `qa-kitchen@example.com` / 주방 |
| 홀 담당 | `qa-hall@example.com` / 홀 |
| 테스트 매장 | `QA 한결 다이닝` |
| 테스트 업체 | `QA 푸른식자재`, `QA 그린패키지` |
| 테스트 품목 | 주방: 감자 10kg, 양파 5kg / 홀: 냅킨 20묶음, 쇼핑백 10묶음 |

## 공통 완료 기준

- 회원가입과 로그인에 이메일 인증 또는 외부 인증 화면이 필요하지 않다.
- 다른 매장의 영수증·업체·품목·재고는 조회하거나 수정할 수 없다.
- 권한 없는 사용자의 확정·금액 수정·재고 조정 요청은 서버에서 거부한다.
- 발주 확정 뒤 영수증, 업체 합계, 품목 비용, 재고 원장이 같은 금액·수량으로 반영된다.

## TS-01 — 관리자 가입 및 첫 매장 생성

**사용자 상황:** 새 식당을 오픈한 점장이 처음 OrderFit을 설정한다.

| 단계 | 사용자 행동 | 기대 결과 |
| --- | --- | --- |
| 1 | 로그인 화면에서 `새 관리자 계정 만들기` 선택 | 이메일·비밀번호·비밀번호 확인 필드가 보인다. |
| 2 | 유효한 이메일과 8자 이상 비밀번호 입력 | 이메일 인증 메일 발송 없이 즉시 계정이 생성된다. |
| 3 | `QA 한결 다이닝` 입력 후 매장 생성 | 매장이 생성되고 가입자는 `admin` 역할을 가진다. |
| 4 | 새로고침 | 로그인 상태와 매장명이 유지된다. |
| 5 | 로그아웃 후 같은 계정으로 로그인 | 관리자 역할과 같은 매장이 복원된다. |

**판정:** 계정 생성·세션 발급·매장 생성·재로그인이 모두 성공하면 통과.

## TS-02 — 역할 부여 및 권한 경계

**사용자 상황:** 점장이 주방과 홀 담당자에게 최소 권한을 부여한다.

| 단계 | 사용자 행동 | 기대 결과 |
| --- | --- | --- |
| 1 | 관리자가 주방·홀 계정을 매장에 초대하고 역할 지정 | 각 계정이 동일 매장에만 연결된다. |
| 2 | 주방 계정 로그인 | 주방 발주 등록·조회는 가능, 확정과 금액 수정은 불가하다. |
| 3 | 홀 계정 로그인 | 홀 발주 등록·조회는 가능, 확정과 재고 조정은 불가하다. |
| 4 | 관리자가 로그인 | 모든 검토·확정·마스터 관리 기능을 사용할 수 있다. |
| 5 | 주소 또는 API 요청을 바꿔 다른 매장 ID 접근 시도 | `403` 또는 데이터 없음으로 거부된다. |

**판정:** 화면 숨김뿐 아니라 서버 API에서도 역할 제한이 지켜져야 통과.

## TS-03 — 주방 배송 영수증 등록

**사용자 상황:** 오전 10시 식자재 배송을 받은 주방 담당자가 영수증을 촬영한다.

| 단계 | 사용자 행동 | 기대 결과 |
| --- | --- | --- |
| 1 | `+ 영수증 등록` 선택 | 날짜·업체·사진 입력 화면이 모바일에서 깨지지 않는다. |
| 2 | 오늘 날짜, `QA 푸른식자재`, 영수증 사진 입력 | 업로드 진행 상태와 실패 시 재시도 안내가 보인다. |
| 3 | 등록 완료 | 해당 날짜에 `검토 필요` 영수증과 원본 사진이 생성된다. |
| 4 | OCR 결과 확인 | 감자·양파, 수량·단가·금액이 행별로 표시되고 신뢰도 낮은 값이 강조된다. |
| 5 | 주방 계정으로 확정 시도 | 확정 버튼이 보이지 않거나 서버가 거부한다. |

**판정:** 원본·거래·품목 초안이 같은 영수증 ID로 연결되면 통과.

## TS-04 — 관리자 검토·확정 및 재고 반영

**사용자 상황:** 점장이 점심 영업 전 미확정 영수증을 처리한다.

| 단계 | 사용자 행동 | 기대 결과 |
| --- | --- | --- |
| 1 | 영수증 목록에서 `검토 필요` 필터 선택 | TS-03의 영수증만 보인다. |
| 2 | 원본 사진과 OCR 품목을 비교 | 업체명, 날짜, 품목, 수량, 단가를 수정할 수 있다. |
| 3 | 품목 합계와 영수증 총액 비교 | 불일치 시 경고하며 확정 전 수정할 수 있다. |
| 4 | `발주 확정` 선택 | 상태가 `확정`으로 바뀌고 재확정이 방지된다. |
| 5 | 재고 화면에서 감자·양파 확인 | 확정 수량만큼 주방 재고 입고 원장이 증가한다. |
| 6 | 업체·품목 상세 확인 | 업체 누적 금액, 품목별 발주 금액·최근 단가가 함께 갱신된다. |

**판정:** 영수증 총액, 품목 합계, 재고 원장, 업체 집계가 일치하면 통과.

## TS-05 — 홀 소모품 발주 분리

**사용자 상황:** 홀 담당자가 냅킨·쇼핑백 영수증을 등록한다.

| 단계 | 사용자 행동 | 기대 결과 |
| --- | --- | --- |
| 1 | 홀 계정으로 영수증 등록 | 품목 영역을 `홀`로 선택할 수 있다. |
| 2 | 관리자가 검토·확정 | 홀 품목은 주방 품목과 분리된 영역으로 저장된다. |
| 3 | 재고 화면에서 영역 필터 변경 | 홀 재고와 주방 재고가 섞이지 않는다. |
| 4 | 월간 비용 화면 확인 | 업체 합계에는 모두 포함되지만 영역별 세부 합계로 나눠 볼 수 있다. |

**판정:** 영역별 재고·품목·필터가 서로 침범하지 않으면 통과.

## TS-06 — 날짜·업체·품목 상세 추적

**사용자 상황:** 점장이 "지난주 포장 용기 비용"을 확인한다.

| 단계 | 사용자 행동 | 기대 결과 |
| --- | --- | --- |
| 1 | 영수증에서 날짜 범위와 `QA 그린패키지` 선택 | 해당 기간 거래 건수와 합계가 보인다. |
| 2 | 날짜 행 선택 | 그날의 업체별 영수증과 발주 품목이 나타난다. |
| 3 | 영수증 상세 선택 | 원본, 품목별 수량·단가·금액·수정 이력·확정자가 보인다. |
| 4 | 품목 상세에서 `포장 용기` 선택 | 발주 날짜별 금액, 업체별 단가, 누적 사용량이 보인다. |

**판정:** 목록 → 날짜 → 영수증 → 품목의 모든 링크가 같은 거래로 연결되면 통과.

## TS-07 — 오류·보안 회귀 테스트

| 검증 항목 | 절차 | 기대 결과 |
| --- | --- | --- |
| 중복 가입 | 같은 이메일로 회원가입 | 중복 계정이 생기지 않고 로그인 안내가 보인다. |
| 잘못된 비밀번호 | 다른 비밀번호로 로그인 | 계정 존재 여부를 과도하게 노출하지 않고 로그인 거부한다. |
| 세션 만료 | 만료된 쿠키로 API 호출 | 로그인 화면으로 이동하고 데이터는 반환하지 않는다. |
| 파일 제한 | 20MB 초과·허용하지 않은 형식 업로드 | 업로드 전에 오류를 보여 주고 파일을 저장하지 않는다. |
| 중복 영수증 | 같은 날짜·업체·금액 영수증 재등록 | 중복 가능성 경고와 원본 비교 경로를 제공한다. |
| 확정 후 수정 | 확정 영수증의 금액 수정 요청 | 관리자도 정정 절차 없이 직접 변경할 수 없다. |
