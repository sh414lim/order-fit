## TS-01 실행 기록

1. 배포본에서 `새 관리자 계정 만들기`를 선택했다.
2. QA 이메일과 8자 이상 비밀번호로 가입했다.
3. 인증 메일·인증 대기 화면 없이 곧바로 `매장을 등록해 주세요` 화면으로 이동했다.
4. `QA 자동 테스트 매장`을 생성했고, 계정 버튼이 `로그아웃 · 관리자`로 표시됐다.
5. 로그아웃 시 로그인 탭으로 전환되는지 확인했다.
6. 같은 QA 계정으로 재로그인했고, 같은 매장명과 관리자 역할이 복원됐다.

## 확인된 이슈와 다음 우선순위

1. **P0 — 발주 API를 독립 세션으로 전환**: 영수증 업로드, 업체·품목 조회/수정, 검토·확정, 재고 원장을 Vercel API에서 `orderfit_user_sessions`와 `orderfit_user_memberships`로 검사해야 한다.
2. **P0 — 역할 관리 화면**: 관리자가 주방·홀·직원 계정을 초대하고 역할을 부여·변경할 수 있어야 한다.
3. **P0 — 파일 업로드 서버화**: 영수증 파일을 서버에서 세션·조직 확인 후 private Storage에 저장하고, 허용 형식·크기를 검증해야 한다.
4. **P1 — 실제 데이터 상세 검증**: 날짜별 거래 → 영수증 원본 → 품목별 금액 → 업체 누적금액 → 재고 원장을 하나의 QA 발주로 자동 검증한다.

## 결론

가입·로그인·매장 생성은 Supabase 이메일 인증과 분리된 실제 DB 세션으로 검증됐다. 반면 발주 도메인은 아직 기존 Supabase Auth RLS 호출에 남아 있어, 독립 회원 체계와 연결하는 서버 API 전환이 MVP 출시 전 최우선 작업이다.
